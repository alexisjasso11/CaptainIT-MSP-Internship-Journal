## What I Did

### Terraform & Ansible — Combined IaC Study

- Spent the day studying **Terraform** as an Infrastructure as Code tool:
  - Terraform provisions and manages cloud infrastructure (VMs, networks, storage, resource groups) by defining it in code rather than clicking through a portal
  - Uses declarative configuration files — you define the desired state, Terraform figures out how to get there
  - Directly applicable to Azure — Terraform has a native Azure provider for provisioning resources
- Revisited **Ansible** in a new context — not just as a standalone automation tool, but as the **configuration management layer** that works after Terraform has provisioned the infrastructure:
  - Terraform builds the environment (spins up the VM, sets up the network)
  - Ansible then configures what's inside it (installs software, applies settings, enforces baselines)
- Understood why these two tools are used together in production cloud engineering workflows — each handles a different layer of the automation stack

---

## What I Learned
The Terraform + Ansible combination clicked because they solve two different problems that naturally follow each other: Terraform answers "what infrastructure should exist," and Ansible answers "what should be on and configured inside that infrastructure." Using them together means an entire environment — from resource provisioning to software configuration — can be defined in code, version controlled, and deployed consistently every time. This is directly relevant to the AZ-104 path and the longer-term goal of cloud security engineering, where repeatable, auditable infrastructure is a security requirement, not just a convenience. Studying these tools during the internship, even without hands-on labs yet, builds the conceptual foundation to start applying them in the home lab next.
